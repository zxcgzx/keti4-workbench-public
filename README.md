# 运行方式智能调整平台B

## 启动

双击 **start-workbench.cmd**，保持窗口打开，在浏览器访问 **http://localhost:8014**。

平台使用 Python 3.11。前端已构建，正常使用不需要 Node.js，页面资源均从本机加载。新电脑首次使用先执行：

```powershell
python -m pip install -r requirements.txt
```

也可手动启动：

```powershell
python run.py --port 8014
```

## 功能入口

| 页面 | 功能 |
|---|---|
| 建模工作台 | 指令输入、L1–L4、动态建模、方程确认、五层校验、黑盒求解、结果地图、风险协商 |
| 历史计算 | 905 节点 E2 方案、16 时段电压与出力、开断矩阵、N−1 结果 |
| 测评模式 | 导入 JSON / CSV 指令集，按 L1–L4 统计，导出报告 |
| 研究模块 | 节点与时空聚合预览、子任务入口、CMDP 与强化学习功能状态 |
| 数据与接口 | 统一数据包、断面质量、测点静态 / 动态预览、设备坐标与外部服务 |
| 功能清单 | M1–M10 与跨课题接口的完整状态 |

## 推荐演示

**基础闭环：** 选择 D1 → 解析 → 确认模型 → 五层校验 → 基态风险与协商 → 采纳建议 → 补全新版参数 → 再确认。

**动态启停建模：** 解析指令后进入模型规格 → 切换模型与目标 → 选择 AC-OTS 和机组启停 → 填写最小开机 / 停机时段与初始已持续时段 → 选择目标 → 应用配置 → 确认并试构建。默认网状支路下，16 时段包含 3,600 个线路状态、3,792 个机组状态以及 7,584 个启停事件二进制变量。

**L4 多轮追问：** 选择 D7，高温降额与少动开关 → 回答时段和降额幅度 → 确认推断 → 对照规格、方程、代码。

**真实历史方案：** 打开“历史计算”，查看 E2 滚动工况、机组出力、母线电压、L151 开断矩阵及事故结果。

**无解诊断：** 输入“第1时段，机组G237有功出力设为2000MW。”，运行校验后定位出力目标与容量上限冲突。

## 数据与计算模式

统一数据包在 `data/905节点计算.zip`，原始断面在 `data/snapshots`，历史方案在 `data/history_905`。

当前建模输入为一个 905 节点断面，16 时段使用“单断面演示模式”。历史 E2 是独立的 MATPOWER / MIPS 计算工况。模型缺少真实机组成本、新能源可用出力或设备坐标时，可在对应页面导入，不自动生成这些数据。

求解器是黑盒，支持演示占位、结果导入和外部适配器。演示占位不产生调整后方案；已有 IPOPT 代码保留在数据包中。新任务求解需配置匹配的外部适配器及数据。

N−1 页面分别标识直流筛查和历史交流校核；当前 E2 历史方案仍有 4 个失败事故。连续潮流、电压稳定裕度、强化学习、实际测点映射及外部团队方法按功能清单显示接口或开发状态。

## 开发

```powershell
# 修改前端后重新构建
cd frontend
npm ci
npm run typegen
npm run build
cd ..
# 后端测试与浏览器流程测试
python -m pytest backend/tests -q
python scripts/test_browser_v4.py
# 生成完整交付包
python scripts/package_v4.py
```

主题变量：`frontend/src/styles/tokens.css`。嵌入入口：`/embed/workbench`。API 文档：`/docs`。

完整交付包：`deliveries/运行方式智能调整平台B-v4.0.zip`。压缩包不包含本机密钥、运行数据库、Python 环境或 node_modules。
