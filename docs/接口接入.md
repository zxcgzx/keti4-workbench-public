# 运行方式智能调整平台B · 接口接入

所有接口均由本地 Python 服务提供；交互式文档为 `/docs`。复制 `.env.example` 为 `.env`，修改后重启。

## 1. 建模服务

| 服务 | 环境变量 | 调用方式 |
|---|---|---|
| 本地 Qwen / 兼容模型 | LLM_BASE_URL、LLM_MODEL、LLM_API_KEY | POST {base}/chat/completions |
| ProOPF 微调模型 | PROOPF_BASE_URL、PROOPF_MODEL、PROOPF_API_KEY | 同上 |
| 铮昊动态建模 | METHOD_ENDPOINT | POST {endpoint}/parse；POST {endpoint}/check |
| 课题 2 大模型 | TOPIC2_MODEL_ENDPOINT | POST {endpoint}/parse |
| 幻觉处置方法 | HALLUCINATION_ENDPOINT | POST {endpoint}/check |

兼容模型的 BASE_URL 应包含版本路径，例如本地 `/v1`，不要再追加 `/chat/completions`。模型 ID 使用服务实际提供的名称。

`/parse` 输入包含 `instruction`、`snapshot_meta`、参数白名单和结构算子；输出包含 `delta_pi`、`structural`、`questions`，以及可选的 `level`、`notes`。每条修改使用 B / L / G 稳定编号并携带原文条件。服务异常时页面明确显示回落到规则引擎。

`/check` 接收规格、原始指令和本地检查结果，返回 `findings` 数组。条目包含 `layer`、`code`、`severity`、`message`、`item_id` 和 `suggestion`。

## 2. 求解黑盒

仅在服务端配置 `SOLVER_CMD`。命令支持 `{spec}`、`{snapshots}`（也可用 `{dir}`）与 `{out}` 占位符：

```text
python adapter.py --spec {spec} --snapshots {snapshots} --out {out}
```

适配器读取已确认规格和实际断面，在唯一输出路径写入结果 JSON。进程有时限和日志；退出失败、输出缺失、非法编号、长度错误和非有限数值均会被拒绝。实际可支持的模型类型和事故范围由适配器检查，不支持的规格应明确报错。

```json
{
  "status": "feasible",
  "solver": "外部求解器名称",
  "objective": null,
  "periods": 16,
  "timings_s": {},
  "branch_status": {},
  "gen_p": {},
  "bus_vm": {},
  "branch_flow": {},
  "messages": []
}
```

`branch_status` 以 L 编号为键、数组值为 0/1；`gen_p` 以 G 编号为键、单位 MW；`bus_vm` 以 B 编号为键、单位 p.u.；`branch_flow` 的每条支路含 `pf`、`qf`、`pt`、`qt` 四条时序，单位 MW / Mvar。时序长度等于 periods。完整 schema 在 `backend/app/solver/result_schema.json`。

已有 IPOPT 增量工程与 MATLAB 工程保留在统一数据包中。它们不自动代替任意新规格；需配置数据、权限、编号和模型转换后接入。

## 3. 课题 3 风险与 Reward

`RISK_ENDPOINT` 为完整 POST 地址，接收任务 ID、版本、指标与结果摘要。至少返回：

```json
{"risk_level":"中","reasons":["风险原因"],"reward":null}
```

没有外部风险服务时使用页面明确标注的本地模拟。Reward 的独立服务入口保留 `REWARD_ENDPOINT`，状态为接口预留；目前不会自动产生强化学习奖励。

协商由平台基于当前评估生成建议。选择建议后写入新的规格草稿；参数幅度由用户补全并重新确认。评估与当前版本不一致时要求重新评估。

## 4. 测点和设备操作

| 表 | 字段 |
|---|---|
| 静态测点 | point_id、device_id、node_id、measurement、unit |
| 动态测点 | point_id、timestamp、value、quality |
| 操作回写 | task_id、version、device_id、operation、value、unit、effective_time |

`POST /api/measurements/preview` 预览 CSV / XLSX，不执行测点映射或设备操作。实际标识对应、单位转换和操作许可由课题 2 与数据方提供。

## 5. 坐标、成本和新能源数据

`POST /api/coordinates`：multipart 文件 CSV，列 `bus_id,longitude,latitude`，WGS84。导入后本地保存并供地图使用。

`POST /api/model-resources/preview?kind=cost`：列 `generator,c2,c1,c0`，检查后返回成本字典与完整性。

`POST /api/model-resources/preview?kind=renewable`：列 `generator,period,available_mw`，每台机组需完整 16 时段。

`GET /api/data/templates/{kind}` 可下载上述模板。模板没有虚构设备或数值行。

## 6. 数据、模型和历史记录

- `GET /api/data/package`：统一数据包摘要。
- `GET /api/data/package/download`：统一 ZIP。
- `POST /api/tasks/{task_id}/configure`：模型类型、机组控制、目标组合及版本修改。
- `GET /api/tasks/{task_id}/model-package`：确认版模型、数据、规格与构建脚本。
- `GET /api/history`、`GET /api/history/{id}`、`GET /api/history/{id}/download`：历史方案。
- `POST /api/aggregation/preview`：节点与时间分组预览。
- `GET /api/research/cmdp`：后续 CMDP 接口结构。

## 7. 宿主平台

`/embed/workbench` 隐藏顶级导航，供宿主页面嵌入。主题变量集中在 `frontend/src/styles/tokens.css`。账号、单点登录、宿主权限及部署网络需在对接时配置。当前服务默认只绑定 `127.0.0.1`，不开放到公网。
